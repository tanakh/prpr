# The generated API

`grammar!`, `include_grammar!` and the `prpr` command generate the same items from a grammar.
This chapter describes them, taking this grammar as an example:

```rust,ignore
prpr::grammar! {
    pub list: Vec<i64> = "[" xs:(number, ",")* "]" { xs }

    #[label = "number"]
    atom number: i64 = s:([0-9]+) { #s.parse().unwrap() }
}
```

In outline, it generates:

```rust,ignore
pub fn list<'i>(input: &'i str) -> Result<Vec<i64>, prpr::ParseError>;
fn number<'i>(input: &'i str) -> Result<i64, prpr::ParseError>;

pub enum Rules {}

impl Rules {
    pub fn list<'i>(cx: &mut Cx<'i, str>, memo: &mut Memo<'i>, pos: usize) -> PResult<Vec<i64>>;
    fn number<'i>(cx: &mut Cx<'i, str>, memo: &mut Memo<'i>, pos: usize) -> PResult<i64>;
}

#[derive(Default)]
pub struct Memo<'i> { /* private fields */ }
```

| item | what it is for |
|---|---|
| a function for each rule | Parsing a whole input. |
| the type `Rules` | Matching a rule at a position, from other grammars or from Rust code. |
| the struct `Memo` | The state of a parse besides the input. |
| items whose names start with `__` | Helpers of the generated code; they are hidden from the documentation. |

The Rust items written in the grammar are copied as they are.
`Cx` and `PResult` are defined in `prpr::runtime`.

## Entry functions

For each rule, a function with the name and the visibility of the rule parses a whole input.
It takes a `&'i str`, or a `&'i [u8]` with [`#![input = bytes]`](../guide/binary-input.md), and returns the value of the rule or a `ParseError`:

* The rule must match all of the input, otherwise the function fails.
* For a syntactic rule, whitespace is skipped at the start and at the end of the input.
  An atom skips nothing.
* When the input does not match, it is parsed a second time to find out what was expected (see [Error messages](../guide/errors.md#how-errors-are-found)).
* Doc comments on the rule become the documentation of the function.

Each call creates the state of its parse and drops it at the end; there is no global state, so the functions can be called from several threads at once.
The functions of private rules are private; they are allowed to be unused, so that rules used only by other rules cause no warnings.

`ParseError` and the types it uses, `Expected`, `Found` and `LineCol`, are defined in `prpr::runtime` and also exported at the root of the `prpr` crate.

## Rule functions

`Rules` is a type without values, whose associated functions are the rules, with the visibility of the rules.
Being associated functions, they are called by their paths, such as `Rules::list`, and cannot be imported with `use`.
Each matches its rule at a byte offset of the input and returns its value and the offset after it, or fails:

```rust,ignore
pub type PResult<T> = Result<(T, usize), Fail>;
```

Unlike entry functions, it does not need to reach the end of the input, and a syntactic rule does not skip whitespace after its last token.
An atom does not check that it is [delimited](../guide/whitespace.md#delimiters); grammars that use it as a token check that.

Rule functions are how [other grammars](../guide/composing.md) use the rules of a grammar.
From Rust code, `prpr::runtime::parse_prefix` runs one at the start of an input.
For more control, call a rule function with a context and a `Memo` of your own:

```rust
mod stmts {
    prpr::grammar! {
        pub stmt: (&'i str, i64) = name:ident "=" value:number ";" { (name, value) }

        atom ident: &'i str = s:([a-z]+) { #s }

        atom number: i64 = s:([0-9]+) { #s.parse().unwrap() }
    }
}

use prpr::runtime::Cx;

fn main() {
    let input = "a = 1; b = 2; c = ;";
    let mut cx = Cx::new(input);
    let mut memo = stmts::Memo::default();
    let mut pos = 0;
    let mut values = Vec::new();
    while let Ok((value, next)) = stmts::Rules::stmt(&mut cx, &mut memo, pos) {
        values.push(value);
        pos = next;
    }
    assert_eq!(values, [("a", 1), ("b", 2)]);
    assert_eq!(cx.error().to_string(), "expected `[0-9]`, found `;`");
    assert_eq!(cx.error().offset(), 18);
}
```

The context, `Cx`, holds the input and records what was expected where parsing failed, and `cx.error()` makes a `ParseError` of the farthest failure.
`Cx::without_errors` makes a context that records nothing, which is faster, when errors are not needed.

## `Memo`

A `Memo` holds the state of a parse: the results of [memoized](../guide/memoization.md) rules, including those of other grammars the grammar uses, and where the whitespace at each position ends.
Create one with `Memo::default()` for each input, and use it with that input only.
Entry functions and `parse_prefix` create their own.

## The runtime

The generated code calls the runtime, the `prpr-runtime` crate, which is also `prpr::runtime`:

* Code generated by `grammar!` and `include_grammar!` refers to it as `::prpr::runtime`, so the `prpr` crate must be a dependency under that name.
* Generated files refer to the `prpr-runtime` crate, to a copy of the runtime in the project, or include the runtime themselves; see [Grammar files and the prpr command](cli.md).
  When they refer to a runtime that is not part of them, they check at compile time that its version is compatible.

## Names

Every rule adds its function to the scope of the grammar, besides `Rules`, `Memo` and the helpers, so the Rust items of the grammar must not use these names.
Names that start with `__` are reserved for the generated code.
Put each grammar in a module of its own, as the examples of this book do, to keep its items apart from other code.
